## 关键认知（踩过的坑，别重复）

### 1. 任务选型：要用 `自动推图`，不是 `自动剧情`

| 任务 | 入口 | 覆盖范围 |
|---|---|---|
| 自动剧情 | `工具-剧情跳过-任务开始层` | **仅**剧情对话中点跳过，共 8 节点 |
| 自动推图 | `工具-自动推图-任务开始层` | 全流程循环，共 35 节点 |

`自动剧情` 必然在结算页/地图页停下——那些节点根本不在它的图里。
作者在任务描述中明确写了「不要跟自动推图放一块运行」，因为 MFA 队列是**顺序执行**，
`自动剧情` 空转会堵住整个队列。

`自动推图` 的 35 节点分三组：
- `自动推图.json`(13)：选关、关卡已结束、可直接下一关
- `剧情处理.json`(14)：跳过、分支选择、调查、骰子、结束事件
- `战斗处理.json`(8)：编队、开始挑战、自动战斗

### 2. 失配分数的含义（诊断用）

| 分数区间 | 含义 |
|---|---|
| 0.1 ~ 0.5 | 画面上压根没这东西，或 ROI 位置错了 |
| 0.6 ~ 0.7 | 可能是繁中字形差异 |
| > 0.85 | 正常命中 |

**不要一看到失配就去补 `resource_TC`。** 本次排查中，绝大多数问题是
ROI 位置错 / 模板带背景，跟繁简无关。

### 3. 繁中弹窗布局与简中不同

繁中确认框比简中**更高**，内部元素整体下移约 32~88px。
所有按简中写死的 ROI 和 Click target 都会落空。模板本身往往是好的
（实测 `未选中不再显示.png` 匹配 0.999），**只是位置错了**。

### 4. 半透明图标模板的通病

剧情界面的 `▷|`、`▶`、对话气泡等都是半透明图标**直接叠在剧情画面上**，
模板截取时把当时的背景一起截了进去。实测亮像素占比仅 5%~23%，
其余全是背景 —— 背景一换分数就崩。

离线验证（合成三种背景）：
- 普通模板：0.766 ~ 0.926（阈值 0.7，余量极小）
- `green_mask` 版：1.000 / 1.000 / 1.000

**修法**：把非图标像素涂纯绿 `(0,255,0)`，pipeline 开 `"green_mask": true`。

## 已做修改

### 原则：简繁共用的放 `resource/`，繁中独有的放 `resource_TC/`

`interface.json` 里「繁中」资源是 `./resource` + `./resource_TC` 叠加加载。
实测 MaaFW 对同名节点是**字段级合并**（只覆盖写到的字段，其余保留），
所以繁中布局差异只需在 `resource_TC/pipeline/` 里写差异字段即可，
**不要直接改 `resource/pipeline/` 里的坐标**，否则简中用户会被改坏。

> 第一轮（commit 22ac2f0）把繁中弹窗坐标直接写进了 `resource/.../剧情跳过.json`，
> 第二轮已恢复为简中原值，繁中差异挪到 `resource_TC/pipeline/单线程工具/繁中跳过确认弹窗.json`。

### 简繁通用（`resource/`）

| 节点 | 改动 | 依据 |
|---|---|---|
| `工具-剧情跳过-点击跳过按钮` | roi `[976,0,92,88]`→`[950,0,120,88]`，开 `green_mask` | 图标在 x962~1002 被切；半透明图标背景不可靠 |
| `工具-自动推图-已进入剧情` / `-点击跳过按钮` | 同上 | **第一轮换了共用的 `跳过按钮.png`（green_mask 版）却没改这两个节点，导致自动推图在剧情里完全认不到跳过按钮**（实测 stall），已同步 |
| `工具-自动推图-任务开始层` | next 增加 `关卡已结束`、`剧情结束确认` | 从结算页启动时原来直接卡死 |
| `工具-自动推图-已进入战斗` | next 增加结算页节点 + 自循环 | 右上角自动战斗图标会被角色台词气泡挡住，三种战斗状态都认不到（0.43），20s 超时后任务失败——而实际战斗已在自动进行并打赢 |
| `工具-自动推图-编队未配满` 等 3 个新节点 | 认到空位十字 → 打开「預設」→ 选第 1 队 → 載入 | 部分关卡首次进入时队伍为空，点「進入」只弹「尚有未配置資料的欄位。」，原流程无限点击。模板是图形（十字、底部人物图标），不含文字 |

| `工具-自动推图-任务开始层` | next 再加 `已进入战斗` | 支持在战斗中启动 |
| `工具-自动推图-战斗中_正在自动战斗` / `-点击进行自动战斗` / `-不可自动战斗` | roi 统一扩到 `[1000,0,200,80]` | 右上角按钮条的图标位置随关卡变化：剧情战斗里🔒实测在 x1053，原 ROI（x1089~1161）落空 → 识别不到「不可自动战斗」，第 1 回合就停住不出牌。扩后 0.981 |
| `通用战斗-检查卡牌位置_*`（6 个） | roi `[0,0,1280,612]` → `[0,360,1280,360]` | 下边界 612 把手牌下半截切掉，模型在裁切图上一张牌都认不出（整图检测时攻击牌 0.93）。只取下半屏 |
| `通用战斗-手牌已空` / `-确认`（新） | 手牌出完但费用≠0 时结束回合 | 原流程只在「0 费」时结束回合；手牌打光还剩 1 费时所有节点都不命中 → 超时失败。放在 next 最后，1.5s 后重新检查一遍卡牌仍没有才点结束，防发牌动画误判 |

新模板：`单线程工具/自动推图/战斗任务/编队空位.png`（空位 1.0 / 满编 0.34）、
`队伍预设界面.png`（预设页 1.0 / 编队页 0.37）、`战斗/回合结束按钮.png`（战斗中 ≥0.99 / 其他页面 ≤0.47）。

> `通用战斗.json` 目前只被自动推图和 `测试.json` 引用，改动不影响肉鸽。

### 实机验证结果（第二轮，第 2 章「雪地上燃起的火焰」）

用 `tools/debug_autopush.py`（见下文）直接驱动 MaaFW，不经过 GUI，连续跑通：

- 剧情关：跳过 → 结算 → 回选关 ✅（多次）
- 战斗关（可自动）：编队 → 进入 → 自动战斗 → 结算 ✅（多次，含图标被台词气泡遮挡的情况）
- 战斗关（队伍为空）：载入预设第 1 队 → 进入 ✅（B03，手动验证流程后接入 pipeline）
- 剧情中的战斗（锁定自动）：识别🔒 → 手动出牌 → 手牌出完结束回合 → 打赢 ✅
- 选关页滑动检查 → 发现新关卡 ✅

未覆盖：分支选择、调查、骰子、结束事件、故事讲述、卡厄思关、跳过确认弹窗（账号已勾「不再显示」）、战斗失败。

### 繁中独有（`resource_TC/pipeline/单线程工具/繁中跳过确认弹窗.json`）

对 `工具-剧情跳过-*` 和 `工具-自动推图-*` 两套节点同时生效：

| 节点 | 简中原值 | 繁中覆盖 |
|---|---|---|
| `跳过确认` | 认标题文字模板 | **And**：勾选框模板（`未/已选中不再显示.png`，roi `[500,440,110,75]`）+ 橙色按钮 ColorMatch |
| `不再显示-已/未选择` | roi `[494,338,95,92]` | `[500,440,110,75]` |
| `不再显示-已选择` 点击 | target `[677,436,330,36]` | `[649,524,390,56]` |

单用 ColorMatch 时，关卡结算页紫色確認按钮能算出 6148（阈值 8000），有误判风险；
结算页没有勾选框，加 And 后排除。
⚠️ 测试账号已勾过「不再显示」，**此弹窗本轮未能实机触发**，参数沿用第一轮实测值（勾选框 0.999、橙色 20463）。
